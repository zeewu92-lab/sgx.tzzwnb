時光線（Timeline） 是一款以「時間」為核心的日程與生活記憶管理應用程式。

它將世界時鐘、倒數日、日程、相冊與資料同步整合在同一個介面中，讓重要的日期可以被計算、被提醒，也可以被保存。

官方網站：https://timezzw.top/

---

✨ 主要功能

🌍 世界時鐘

查看世界各地目前時間，適合跨時區生活、旅行、遠距工作與聯絡海外朋友。

你可以：

- 新增不同國家與地區的時區
- 使用國旗與地區名稱快速辨識
- 查看當地目前時間
- 將某個時區設定為「目前位置」
- 查看其他地區與目前位置的時差
- 使用精簡／詳細顯示方式查看時間
- 在時區較多時獨立捲動時區清單
- 在手機、折疊式裝置、平板與桌面螢幕上使用

目前程式內已建立多個常用地區與時區資料，包括亞洲、歐洲、北美洲、大洋洲等地區；美國等多時區國家也會提供進一步的時區選擇。

⏳ 時間軸

時光線的核心功能。

你可以建立一個「地標」，記錄任何值得記住的日期，例如：

- 生日
- 旅行
- 認識某人的日子
- 紀念日
- 重要計畫
- 活動
- 任何個人重要日期

建立事件時可以設定：

- 標題
- 日期
- 時間
- 曆法
- 重複週期
- 模式
- 圖示
- 路標色
- 備註
- 卡片背景圖片
- 數字字體

事件會按照時間排列在時間軸中，清楚呈現「距離那一天還有多久」或「那一天已經過了多久」。

---

📅 多種事件模式

建立事件時可以選擇不同模式。

🎂 生日

將日期設定為生日後，時光線可以按照生日週期計算下一次生日，並自動顯示對應年齡。

例如：

«2010 年出生 → 下一個生日 → 「16 歲生日」»

生日事件也具有專門的生日提示與視覺呈現。

🤝 陪伴

用來記錄一段關係或陪伴開始的日期。

例如：

«2024 年 8 月 26 日開始陪伴
→ 今天已經 732 天»

程式會以「已經多少天」的方式呈現持續時間。

🕯️ 關懷

用於追悼、紀念與保存對逝者的記憶。

關懷模式會使用較為素雅的色彩與專用圖示，例如蠟燭與墓碑，並以週年方式呈現時間。

此外，關懷模式採用 CSS 設計 Token 調整視覺，不會直接對整個畫面套用灰階濾鏡，因此世界時鐘中的國旗等原生彩色元素不會被錯誤地轉成灰色。

🏅 紀念日

用於記錄值得長期保存的特殊日期。

📌 常規

適合不需要特殊語義的普通日期與事件。

目前事件模式系統已經建立統一資料結構，舊版資料也可以依既有生日／關懷欄位轉換為對應模式。部分新模式的進階行為仍會隨後續版本持續完善。

---

🔁 循環事件

事件可以設定重複週期。

目前支援：

- 每年
- 每 N 年
- 每月
- 每 N 個月

這適合生日、週年紀念、週期性活動等。

日期計算也針對月份天數與閏年進行了特殊處理。

例如：

«1 月 31 日 + 1 個月»

不會因 JavaScript 原生日期溢位而錯誤跳到 3 月，而會按照目標月份的實際天數調整到 2 月最後一天。

同樣的處理也套用於閏年 2 月 29 日的週期計算。

🗓️ 日程

「日程」提供更接近傳統日曆的方式查看事件。

支援：

- 年檢視
- 月檢視
- 週檢視
- 月曆選擇日期
- 年份／月份快速選擇
- 收合／展開日曆
- 只顯示未來事件
- 顯示全部事件
- 查看指定日期的事件
- 在日期下方顯示其他曆法

年、月、週三種檢視已在程式中建立為獨立的檢視模式。

🌙 多曆法支援

時光線不只使用西曆。

目前程式支援以下曆法：

曆法| 說明
西曆| Gregorian Calendar
農曆| Chinese Lunar Calendar
伊斯蘭曆| Islamic Calendar
希伯來曆| Hebrew Calendar
佛曆| Buddhist Calendar
日本曆| Japanese Calendar

建立事件時可以單獨指定該事件使用的曆法。

日程頁面則可以選擇要在日期下方額外顯示哪些曆法，而且可以複選。

農曆日期還針對：

- 干支年
- 正月～臘月
- 閏月
- 初一、初二等傳統日期表示

進行了額外處理。

🔔 倒數日提醒

對重要事件設定提醒。

可以：

- 開啟系統通知
- 設定提前幾天提醒
- 對週期性事件分別記錄每一次提醒
- 根據瀏覽器 Notification API 判斷通知支援狀態

目前通知機制會記錄某個事件「上一次已通知的 occurrence」，因此生日等每年重複的事件不會因為剩餘天數相同而被錯誤判定為已經提醒過。

«**注意：**目前網頁通知機制要求網頁／App 保持開啟，背景分頁也可以。部分瀏覽器或平台可能不支援通知。»

🖼️ 相冊

相冊是時光線的獨立功能，用來保存與事件有關或完全獨立的照片。

你可以：

- 建立相冊
- 新增一張或多張照片
- 重新命名相冊
- 刪除相冊
- 刪除照片
- 多選照片
- 將照片移動到其他相冊
- 將相冊與某個事件關聯
- 建立不關聯任何事件的獨立相冊
- 從事件直接進入關聯相冊

相冊與事件之間採用可選關聯：

事件
 ├── 相冊 A
 ├── 相冊 B
 └── 無相冊

獨立相冊
 └── 不關聯任何事件

這使相冊可以同時服務於「事件記憶」與「一般照片整理」兩種用途。

🔐 備份檔案加密

新版 ".tzzwnb" 備份採用 AES-256-GCM 加密。

每次匯出時會產生隨機 IV，並將 IV 與密文組合後保存。

備份格式以：

TZZWNB1:

作為格式識別前綴。

匯入時會先驗證格式，再解密並驗證 JSON 資料結構。

一個重要的技術限制

這個加密主要用於：

«防止備份檔被直接用文字編輯器打開時，一眼看到完整資料。»

目前金鑰材料存在前端程式中，因此它不能被視為真正的機密儲存方案。

任何能取得完整前端程式碼的人，理論上都可以分析並取得解密所需資訊。

因此 ".tzzwnb" 適合作為資料保護與避免直接暴露內容的備份格式，不應被當成密碼保護或高強度機密儲存機制。

☁️ 雲端同步

登入帳戶後，可以啟用雲端同步。

目前帳戶系統整合：

- Email + Password
- Google 登入
- Email Magic Link
- Apple 登入介面
- Firebase Authentication
- Firebase / Firestore 雲端資料同步

登入後，時光線會比較：

本機資料
    ↓
雲端資料
    ↓
是否一致？

如果兩邊資料不同，會讓使用者選擇：

1. 合併兩邊資料
2. 使用雲端資料覆蓋本機
3. 使用本機資料覆蓋雲端

因此重新登入裝置時，不會直接無條件覆蓋其中一邊的資料。

🌏 中國大陸地區

目前 Firebase 帳戶登入與部分雲端服務在中國大陸地區存在可用性限制。

🔧 開發者注意事項

資料儲存

時光線採取「本機優先」的資料模型。

主要資料包括：

events
clocks
albums
album photos
language
theme
custom icons
notification settings

相冊照片沒有全部塞進單一資料結構，而是以獨立的儲存 Key 保存：

album-photos:{albumId}

這樣可以避免某一個相冊照片過多時影響其他資料。

圖片處理

使用者上傳的圖片會先進行處理：

- 最長邊限制
- 等比例縮放
- JPEG 壓縮
- 再轉成 Data URL

目前預設最大尺寸為 1000px，品質設定為 0.85。

這可以降低大型原始照片直接存入本機資料造成的容量壓力。

🧪 Beta / 測試機制

目前專案仍保留 Beta 內測機制。

使用者可以透過邀請碼進入測試版本。

邀請碼本身不直接寫入程式碼，而是先經 SHA-256 雜湊後再進行比對。

目前驗證邏輯設計成可替換架構：

Phase 1
前端 SHA-256 驗證

        ↓

Phase 2
Cloudflare Worker API

未來若改成後端驗證，可以只替換驗證函式，而不必重新設計整個 Invite Gate。

📦 備份格式

時光線使用自訂：

.tzzwnb

作為本機備份副檔名。

目前新版格式：

TZZWNB1:<Base64 encoded encrypted payload>

Payload 使用 AES-GCM 加密。

匯入時會進行：

檔案格式檢查
      ↓
Magic Header 檢查
      ↓
Base64 解碼
      ↓
AES-GCM 解密
      ↓
JSON 解析
      ↓
資料結構驗證
      ↓
匯入

同時支援透過瀏覽器 File Handling API 直接以 ".tzzwnb" 檔案開啟時光線，讓作業系統可以將備份檔交給已安裝的 App 處理。
